# Текущее состояние прототипа Voice Assistant (Electron)

Дата: 2025-12-16

## Коротко о продукте

**Voice Assistant** — Electron-десктоп приложение с голосовым взаимодействием (STT → LLM → TTS), 3D‑персонажем (THREE.js), текстовым чатом и серверной частью (Node.js + MongoDB) для авторизации/настроек/истории.

Монорепа:
- `apps/desktop/` — текущий продукт (Electron main + backend-electron + UI)
- `apps/backend-main/` — API сервер (порт 3001)
- `packages/shared/` — общие DTO/Zod/типы

## Что уже реализовано (по факту в коде)

### 1) Desktop UI (React + Redux)

**Экраны (есть код + Playwright снапшоты):**
- `WelcomeScreen` — приветственный экран
- `IdleScreen` — состояние ожидания
- `MainScreen` — главный экран с 3D персонажем (сцена/модель/анимации)
- `ChatScreen` — чат, история, панель диалогов
- `MenuScreen` + подэкраны:
  - `SettingsScreen` — настройки (тема/акцент/и т.п.)
  - `APIKeysScreen` — управление API ключами провайдеров
  - `AuthScreen` — регистрация/логин + OAuth (Google/Yandex/GitHub)
  - `ApplicationsScreen` — «магазин приложений» (каталог/установленные), импорт ZIP, версии
  - `LogsScreen` — просмотр логов
  - `AboutScreen` — информация

**Чат:**
- Локальные диалоги и сообщения в Redux (даты — ISO строки)
- Поддержка markdown/emoji (есть снапшоты для markdown и emoji picker)
- Экранная клавиатура (EN/RU/ZH), рендер через portal, управление высотой через CSS переменные

**Голос в UI (Redux + thunks):**
- `startRecording` / `stopRecordingAndProcess`: запись → распознавание → запрос к LLM → озвучка
- Результаты (распознанный текст/ответ) добавляются в чат как сообщения

### 2) Интеграция Electron (preload/IPC → window.api)

UI использует `window.api.*` для:
- `startRecord()` / `stopRecord()`
- `transcribe(audioBuffer)`
- `askLLM(text)`
- `speak(text)`
- `getLLMProviderInfo()`

(Реализация находится в `apps/desktop/main/` и `apps/desktop/backend-electron/`.)

### 3) Голосовой пайплайн в `apps/desktop/backend-electron/`

**Запись/воспроизведение (кроссплатформенно):**
- Запись и проигрывание через системные утилиты (`arecord/aplay` или `sox`), с проверкой наличия команд

**STT:**
- Провайдеры в конфиге: `whisper_api`, `yandex_stt`, `google_stt`, `vosk`
- Реально реализован сетевой вызов для `whisper_api` (OpenAI Whisper Transcriptions)
- Для остальных провайдеров сейчас fallback/заглушка (возвращает тестовый текст)

**LLM:**
- Провайдеры в конфиге: `openai`, `yandex_gpt`, `anthropic`
- Реально реализован сетевой вызов для `openai` (chat completions)
- Для остальных провайдеров сейчас fallback/заглушка

**TTS:**
- Провайдеры в конфиге: `yandex_tts`, `silero`, `google_tts`
- Реально реализован сетевой вызов для `yandex_tts` + воспроизведение аудио
- Для `silero`/`google_tts` сейчас fallback/заглушка

**Сервисные эндпоинты backend-electron:**
- `GET /health`
- `GET /config` (возвращает текущие провайдеры и маскирует ключи)

### 4) Backend main (`apps/backend-main/`, порт 3001)

**Есть:**
- Регистрация/логин, JWT токены
- OAuth: Google / Yandex / GitHub
- Настройки пользователя (в т.ч. тема/язык/акцент)
- История чатов (диалоги и сообщения) через API
- Шифрование API ключей

**Applications subsystem (каталог/установки/версии/ZIP):**
- Публичный каталог опубликованных приложений
- Создание черновика приложения (авторизовано)
- Статусы: `draft/pending/published/rejected` (есть отправка на ревью/изменение статуса)
- Установка/удаление приложения пользователю
- Импорт ZIP без авторизации (guest → привязка после логина)
- Загрузка новой версии (FormData + ZIP), релиз-ноты, иконка
- Квота хранилища пользователя: лимит 100 MB, хранение в `storage/applications/<user>/<app>/<version>`

### 5) Тестирование/инфраструктура

- Визуальные тесты Playwright для ключевых экранов (снапшоты закоммичены)
- Redux сериализация: даты в state — ISO строки
- Vite бандлинг: React/react-redux/@emotion/react закреплены в основном чанке

## Что НЕ доделано / ограничения текущего состояния

- **STT/LLM/TTS провайдеры частично заглушки**: реально «из коробки» работает OpenAI (STT+LLM) и Yandex TTS; остальные варианты требуют реализации.
- **«Магазин приложений» пока про управление ZIP/версиями/установкой**, но **выполнение/рантайм “приложений/скиллов” в UI/ассистенте не видно** как законченный пользовательский сценарий.
- **Стабильность демо**: завязка на системные аудио-утилиты (`sox`, `alsa-utils`) и ключи провайдеров; без них пользователь увидит мок‑ответы.
- **Онбординг/первые 2 минуты**: нужно убедиться, что новичку понятно, где настроить ключи/провайдера и как получить “первый успешный голосовой ответ”.

## Гипотезы для проверки (в рамках 13 дней)

### H1 (основная)
Пользователь готов использовать **десктоп‑ассистента “голос + чат”** регулярно, если:
- ответ приходит достаточно быстро (ощущается «живым»),
- есть история/контекст,
- есть понятный сценарий применения (например: быстрые вопросы, обучение/помощь по задачам, заметки).

### H2 (дифференциация)
**3D‑персонаж + озвучка** повышают вовлеченность/удержание по сравнению с «обычным чатиком».

### H3 (платформенность — опционально)
Пользователю/создателю ценна идея **установки/импорта “приложений/скиллов” (ZIP)** — но для проверки нужен хотя бы минимальный рантайм/интеграция “скилла” в диалог.

## Что надо доделать для запуска прототипа (MVP для проверки H1/H2)

### Must-have (чтобы прототип был проверяемым)
- **Стабильный end-to-end голосовой сценарий**: запись → реальный STT → реальный LLM → реальный TTS (без моков)
  - Рекомендация под Yandex Startup Lab: реализовать `yandex_stt` + `yandex_gpt` полностью (а `yandex_tts` уже есть).
- **Понятный онбординг**:
  - экран/шаги: “вставь ключи → нажми говорить → получи ответ”
  - проверка `/health` и подсказки по установке `sox/alsa-utils`
- **Минимальный сценарий ценности** (один вертикальный use-case):
  - пример: «помощник для быстрых вопросов + сохранение в историю + озвучка»
  - или «голосовая заметка/саммаризация в чат с сохранением»

### Should-have (усилители качества проверки)
- **Метрики и логирование** (хотя бы локально):
  - время STT/LLM/TTS, ошибки провайдеров, число успешных сессий
- **Стабильность UI/ошибок**: понятные сообщения при отсутствии ключей/микрофона/сети
- **Сравнение H2**: флажок “персонаж/без персонажа” или “озвучка on/off” для быстрых A/B сессий

### Could-have (если останется время)
- Минимальная «интеграция приложения/скилла»:
  - 1 демонстрационный skill, который можно установить/импортировать и вызывать из чата (хотя бы через ключевое слово)

## План на 13 дней (прототип + минимальное исследование)

Цель на конец: **демо‑готовый прототип** + **минимально подтвержденные инсайты** (кому нужен/за что платят/как используют).

- **День 1**: зафиксировать целевой сценарий (H1) и “definition of done” прототипа (1 страница)
- **День 2**: реализовать/довести до конца выбранный стек провайдеров (приоритет: Yandex STT + YandexGPT + YandexTTS)
- **День 3**: улучшить онбординг и сообщения об ошибках (микрофон, ключи, сеть), чек `/health`
- **День 4**: довести UX голосового цикла (статусы LISTENING/RECOGNIZING/GENERATING/SPEAKING), устранить «острые углы»
- **День 5**: добавить минимальную телеметрию (локально/в логи): latency, success rate, тип ошибки
- **День 6**: подготовить “demo script” на 2–3 минуты + сборка/инструкция запуска для тестеров
- **День 7**: 5 интервью/юзабилити-сессий (15–25 мин) с записью наблюдений
- **День 8**: 5–7 дополнительных сессий (другой сегмент), фиксация повторяющихся проблем
- **День 9**: выбрать 2–3 изменения по результатам, быстро внедрить
- **День 10**: повторное тестирование (3–5 человек) после правок
- **День 11**: подготовить короткий лендинг/опрос (если нужно) + собрать ещё 10–20 ответов
- **День 12**: упаковать результаты: кто ЦА, какой JTBD, что подтвердили/опровергли, метрики
- **День 13**: собрать материалы для заявки (описание, демо-видео, план развития)

## Минимальное исследование (чтобы было что написать в заявку)

- **ЦА (стартовая)**: выберите 1 сегмент (например: студенты/разработчики/создатели контента/пользователи с accessibility‑потребностями)
- **Метод**:
  - 10–12 коротких интервью/сессий “дай задачу → используй прототип”
  - 1 мини‑опрос (10–20 ответов) для подтверждения формулировок боли/частоты
- **Что измеряем (просто и достаточно)**:
  - % успешных голосовых циклов без ошибок
  - медианная задержка (STT + LLM + TTS)
  - NPS/оценка полезности (0–10) и “что бы убрало последнюю причину не пользоваться?”
  - готовность повторить завтра / платить (хотя бы гипотетически)
- **Артефакты**:
  - 1 страница инсайтов (топ-5 болей/пожеланий)
  - 3–5 цитат пользователей
  - список принятых решений “что делаем дальше и почему”

## Definition of Done (чеклист «прототип готов»)

- [ ] На чистой машине с инструкцией можно запустить и получить **реальный** голосовой ответ (без моков)
- [ ] Ошибки объяснимы и ведут к действию (установить `sox`, добавить ключ)
- [ ] Есть 1 главный сценарий демо и он работает стабильно 3 раза подряд
- [ ] Собраны минимум 10 сессий с пользователями и 3–5 измеримых выводов
